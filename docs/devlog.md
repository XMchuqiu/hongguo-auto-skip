# 开发过程记录：从 29 KB 的 APK 到 v2.5

> 这份文档按时间顺序记录整件事：起点只有 APK 没有源码、怎么反编译、每一版是根据哪条真机日志/哪张截图改的、改完怎么验证、以及踩过的坑。
>
> 目标应用：红果免费短剧 `com.phoenix.read`、红果免费漫剧 `com.kylin.read`。

---

## 0. 一句话结论

原始版本（v1.0）只对「漫剧」在某些设备上有效；经过 6 个版本迭代，现在支持两个 App、
手机/平板/横竖屏，46 个单元测试覆盖判定逻辑，但**仍未在荣耀 MagicOS 真机上回归**。

---

## 1. 起点：只有 APK，没有源码

工作区里只有一个 29,333 字节的 `红果自动跳过.apk`。第一步是把它还原成可读代码：

1. 环境里没有 java / android sdk / git / 7z，先下载 Temurin JRE + jadx；
2. jadx 起不来：`createTempFile` 报「拒绝访问」——`%TEMP%` 不可写，
   改用 `JADX_CONFIG_DIR/JADX_CACHE_DIR/JADX_TMP_DIR` 指到工作区后成功；
3. 反编译得到 3 个类：`MainActivity`(424 行)、`HongguoAccessibilityService`(340 行)、`AppLog`。

反编译结果保存在 `work/src`（未入库），是后续所有对比的依据。

## 2. v1.0 的问题清单（读代码得出）

| # | 写法 | 后果 |
|---|---|---|
| 1 | 只在 `onAccessibilityEvent()` 里检测 | ROM 合并/丢弃 `TYPE_WINDOW_CONTENT_CHANGED` 时不检测；平板事件派发更宽所以能跑 |
| 2 | 主线程递归遍历整棵树，根节点为空时 `Thread.sleep(200)` | 阻塞主线程 → 掉事件、手势失败、ANR |
| 3 | 只读 `getRootInActiveWindow()` 一个窗口 | 广告在独立/悬浮/广告 SDK 窗口时看不到 |
| 4 | 只有两条判据：「第N集」文本、控件 `id=jer`（漫剧专有）+ 一组落地页词 | **短剧的广告页完全匹配不到 → 永远不上滑** |
| 5 | `<service android:exported="false">` | 系统绑定无障碍服务可能失败 |
| 6 | 默认值前后矛盾（`check_interval` 取了 `DEFAULT_COOLDOWN`、`confirm` 服务端 2/界面 1、`debug_mode` 相反） | 界面显示与实际行为不一致 |
| 7 | 调试模式每个事件 dump 整棵树 | 手机上等于自杀 |
| 8 | 声明 `POST_NOTIFICATIONS` 从不申请 | Android 13+ 通知静默丢弃 |
| 9 | 判定是「看到广告就滑」而不是「广告播完再滑」 | 没实现设计目标，且容易误触 |

## 3. 版本演进

每一版都是「真机日志/截图 → 定位 → 改判定 → 补单测 → 发版」的循环。

### v2.0 — 重写检测链路（10-30 23:53）

**做了**：检测移到独立工作线程轮询（事件只作提示）、`getWindows()` 多窗口、结构化识别
（广告角标/跳过/倒计时/落地页词/上滑提示）、新增「广告播完才滑」状态机、双 App 开关、
`exported=true` + 运行时刷新 `serviceInfo`、通知权限、参数体系统一、诊断抓取。

**验证**：26 个单测；APK 38.9 KB；首次发布（git 的 schannel 证书校验不可用，改用 GitHub API 推送）。

### v2.1 — 「广告还在播就滑了」（10-31 00:36 日志）

日志证据：

```
00:07:41.386 检测: com.kylin.read 广告角标 倒计时=21s 落地页词 继续观看提示 第N集
00:07:41.547 上滑: pkg=com.kylin.read 原因=出现继续观看提示
```

**根因**：底部「上滑继续看短剧」是**广告播放期间就常驻**的提示，不是结束标志。

**修复**：该提示只在「页面上没有正在走的倒计时」时才作为结束信号；新增**点击跳过按钮**（排除
跳过片头/片尾）；上滑力度三段升级；滑动区域取「窗口 ∩ 屏幕」（窗口 2800、屏幕 2659，旧版会滑出屏幕）；
抓取延迟 5 秒；日志可滑动/全屏/打开位置；关键词说明；`<queries>` 修复“已安装 ✗”；横竖屏适配。

**验证**：34 个单测。

### v2.2 — `getWindows()` 只返回状态栏；结束卡片滑不动（10-31 00:52 日志）

日志证据：

```
00:30:36.430 --- 窗口 pkg=com.android.systemui layer=0 active=false ---
00:30:36.431 ===== 页面节点结束 =====
```

**根因 1**：有些时刻 `getWindows()` 只给状态栏，`resolveForeground()` 于是认为前台不是红果，
**整轮检测被跳过**（这解释了“某些广告完全没反应”）。
**根因 2**：结束卡片上 78% 的落点压在广告「点击进入游戏/官方下载」按钮或 WebView 上，手势被广告视图吃掉。

**修复**：`collectRawWindows()` 总是补上 `getActiveWindow` 根节点；第 2/3 次上滑改从 92%/50% 起手；
结束卡片要求连续 600ms 无倒计时；新增「广告卡住 15s 自动切后台再回来」；抓取等待/完成反馈。

**验证**：36 个单测。

### v2.3 — 上滑变成了「下滑回上一集」（10-31 00:52 日志）

日志证据：

```
参数: 间隔=200ms 冷却=500ms 持续=300ms 滑动=155ms 40%->44%
上滑: 坐标=640,1063->1169
```

**根因**：用户把起点设成 40%、终点 44%，手指是往下移动的——界面允许了非法组合。

**修复（三道防线）**：界面拖动时自动纠正（起点必须高于终点 15% 以上）；`DetectorConfig.sanitize()`
统一收口，老配置升级后自动修正；`performSwipe()` 出手前再校验，方向不对强制改成 85%→15%。
同时给**每个设置项加了说明文字**。

**验证**：40 个单测（新增 `DetectorConfigTest`）。

### v2.4 — 广告还剩 17 秒就被判成结束（10-31 01:01 日志）

日志证据：

```
01:00:45.515 检测: 广告角标 倒计时=17s 落地页词 继续提示 第N集
01:00:45.531 检测: 广告角标 落地页词 继续提示        ← 倒计时"消失"
01:00:46.330 上滑: 原因=广告结束卡片（上滑继续）
```

dump 里的根因：

```
id=- desc=[广告] bounds=968,0,1108,-2534
```

**根因**：广告浮层节点高度是负的（被裁到屏幕外），倒计时/第N集 会间歇性“消失”；
0.6 秒的确认窗口扛不住这种抖动。

**修复**：结束卡片确认 0.6s → **2.5s**；「广告标识持续」也加确认窗口——出现过倒计时的广告按 2.5s 算，
从未出现过倒计时的静态广告卡片仍按 1.2s（不变慢）。新增两个单测复现该日志序列。

**验证**：42 个单测。

### v2.5 — 持续上滑模式（独立开关）

需求：广告的播完信号不可靠时，检测到广告就按固定间隔一直滑。

**实现**：独立开关 + 间隔滑杆（300–2000ms，默认 800ms）；只要仍判定为广告且距上次动作 ≥ 间隔就再滑；
持续模式下不进入 4s 长静默；扫描节奏取「检测间隔」与「持续上滑间隔」的较小值；
安全阀：单条广告最多 40 次、广告消失即停且不再补滑（否则多跳一集）。关掉开关即回到 v2.4 逻辑。

**验证**：46 个单测。

## 4. 最终架构

```
app/src/main/java/com/hongguo/auto/
├── MainActivity.java                 界面：开关、参数、诊断、日志、关键词
├── HongguoAccessibilityService.java  无障碍服务：轮询、多窗口、手势/点击/切后台
├── NodeScanner.java                  AccessibilityNodeInfo → UiNode；窗口快照/导出
├── Prefs.java                        参数读写（兼容旧键名，读取即 sanitize）
├── ServiceState.java                 服务↔界面共享状态（含延迟抓取）
├── AppLog.java                       环形日志（500 行）
└── core/                             纯 Java，无 Android 依赖，可在 JVM 上跑单测
    ├── UiNode.java                   节点快照
    ├── AdSignals.java                一次扫描的特征与 isAd()
    ├── AdDetector.java               规则识别
    ├── AdStateMachine.java           何时 点/滑/切后台
    └── DetectorConfig.java           参数 + sanitize
```

**数据流**：`HandlerThread` 轮询 → `NodeScanner` 采窗口 → 只对目标/广告 SDK 窗口建 `UiNode` 树 →
`AdDetector.scan()` 出 `AdSignals` → `AdStateMachine.onScan()` 出一个 `Action`（SWIPE/TAP/ESCAPE）→
服务执行手势 → 状态回写 `ServiceState` 供界面显示。

**纯逻辑与 Android 解耦**是这个项目能做测试的关键：判定规则可以在电脑上跑 46 个用例，
不用连真机。

## 5. 测试与发布

- 单测：`AdDetectorTest` 21（识别规则）、`AdStateMachineTest` 21（时序/冷却/次数/切后台）、
  `DetectorConfigTest` 4（方向自检、越界收敛）。
- 每次发版流程：`gradle :app:testDebugUnitTest` → `assembleDebug/Release` →
  `aapt2 dump badging` + `apksigner verify` → 复制到 `dist/` → 提交 → 打 Release → 下载回来比对 SHA256。
- 因为本机 git 的 schannel 证书链校验不可用，推送走的是 **GitHub Git Data API**
  （上传变化的 blob → 逐层建 tree → 建 commit → 更新 ref），推完校验远端 blob SHA 与本地一致。

## 6. 踩过的环境坑

| 坑 | 处理 |
|---|---|
| DSH 沙箱临时授权目录创建失败，所有命令报错 | 切到完全权限 |
| jadx 无法创建临时文件 | `JADX_*_DIR` 指到工作区 |
| `sdkmanager` 连不上 dl.google.com（Java 网络） | 直接下载官方 zip 手工布局 SDK |
| AGP 不能在 `~/.android` 建 debug.keystore | 项目内自带 `keystore/debug.keystore` |
| git push 报 `CRYPT_E_NO_REVOCATION_CHECK` / 证书链不完整 | 改用 GitHub API 推送 |
| WHPX 下 Android 模拟器起不来 | 放弃端到端模拟，改为规则级单测 + 真机日志迭代 |

## 7. 经验教训

1. **「提示」不等于「状态」**：底部“上滑继续看短剧”在广告播放期间一直存在，把它当结束信号直接导致
   提前上滑（v2.1）。
2. **无障碍树会抖动**：广告浮层节点会被裁到屏幕外（bounds 为负），倒计时、集数节点间歇性消失。
   任何“消失即状态变化”的判定都必须带确认窗口（v2.4 的 2.5 秒）。
3. **`getWindows()` 不可靠**：必须兜底取活动窗口根节点，否则会把“前台是状态栏”当成结论（v2.2）。
4. **用户能设出的值就一定会被设出来**：起点 40% / 终点 44% 直接让手势反向。
   参数校验必须在 UI、参数层、执行层各做一次（v2.3）。
5. **坐标必须相对当前窗口/屏幕**：窗口 bounds 与 display metrics 相差一个状态栏高度，
   百分比落点会滑出屏幕（v2.1）。
6. **可观测性优先**：没有“抓取节点 + 导出日志 + 等待/完成提示”，后面 5 轮定位都不可能发生。
7. **真机日志 > 一切猜测**：五个版本的关键修复，全部来自日志里的具体时间戳与坐标。

# 红果自动跳过 v2.3（修复版）

通过无障碍服务检测「红果免费短剧」「红果免费漫剧」的广告是否播放完毕，然后自动上滑继续播放，无需 Root。

- 包名：`com.hongguo.auto`（与原版一致，可直接覆盖安装；签名不同，需先卸载旧版）
- 目标应用：`com.phoenix.read`（红果免费短剧）、`com.kylin.read`（红果免费漫剧）

## 下载

- 直接安装：[dist/hongguo-auto-skip-v2.3.apk](dist/hongguo-auto-skip-v2.3.apk)（release）
- 自己编译：`./gradlew :app:assembleRelease`。仓库自带调试签名 `keystore/debug.keystore`（密码 `android`，别名 `androiddebugkey`），
  只为让 clone 下来就能构建，**对外分发请换成你自己的签名**。

## v2.3 修复了什么

真机日志（00:52 那份）里的关键两行：

```
参数: 间隔=200ms 冷却=500ms 持续=300ms 滑动=155ms 40%->44%
上滑: 坐标=640,1063->1169
```

**起点 40%、终点 44% —— 手指是从 1063 往 1169 移动，等于“往下滑”，所以红果回到了上一集。**
这是我的界面允许了非法组合：终点必须低于起点，否则手势方向反了。

三道防线：

1. **界面**：拖动时自动纠正，起点与终点必须相差 ≥15%，否则把终点拉回起点上方并提示；
   标签也改成「滑动起点（手指按下位置）」「滑动终点（手指抬起位置）」。
2. **参数层**：`DetectorConfig.sanitize()` 统一收口（间隔≥300ms、冷却≥600ms、方向差≥15% 等），
   读配置和保存时都会走一遍，老版本存下来的非法值升级后自动修正。
3. **手势层**：`performSwipe()` 出手前再校验一次，一旦发现终点在起点下方，直接改成标准的上滑
   （85%→15%），并写日志说明"参数方向异常"。

另外：**每个设置项下面都加了说明文字**，写清楚它影响什么、建议取值范围、以及容易踩的坑
（例如终点高于起点会返回上一集、检测间隔 200ms 会很耗电、广告结束判定与倒计时的关系等）。

## v2.2 修复了什么（基于第二次真机日志）

**1）`getWindows()` 有时只返回状态栏**

```
00:30:36.430 --- 窗口 pkg=com.android.systemui layer=0 active=false ---
00:30:36.431 ===== 页面节点结束 =====
```

抓下来的文件里只有状态栏，红果的窗口一个都没有。更严重的是：这种情况下
`resolveForeground()` 会认为前台是 `com.android.systemui`，于是**整轮检测直接被跳过**。
现在 `collectRawWindows()` 总是补上 `getRootInActiveWindow()` 的根节点，不再依赖 `getWindows()`
是否完整——这一条本身就可能造成"某些广告完全没反应"。

**2）结束卡片上滑没反应**

结束卡片上手指落点（配置的 78%）正好压在广告的"点击进入游戏 / 官方下载"按钮或广告 WebView 上，
手势被广告视图吃掉。现在第二次尝试改成从底部提示条附近（92%）起手，第三次从视频区中部（50%）起手。

**3）"上滑继续看短剧"要稳定才认**

倒计时节点偶尔不渲染，单次扫描没有倒计时就滑会误判。现在要求**连续 600ms 都没有倒计时**才当作结束卡片。

**4）广告怎么都过不去 → 自动切后台再回来**

你验证过的办法（切走再回红果，广告就没了）已经做成开关：广告持续 **15 秒**仍未结束、
没有跳过按钮时，自动回桌面再重新打开红果。设置里可以关掉。

**5）抓取节点现在有反馈**

- 点「抓取当前页面节点」→ 提示"5 秒后抓取，请切回广告页"
- 状态区显示 **抓取节点：等待中，约 N 秒后执行**
- 抓取完成 → **Toast「已抓取 X 个窗口 / Y 个节点」**，状态区显示"最近抓取：时间 · X 个窗口 / Y 个节点"
- 日志里打印窗口列表（包名 + 是否 active），能直接看出抓到了谁

## v2.1 修复了什么（基于第一次真机日志 + 截图）

真机日志里暴露了一个关键 bug：

```
00:07:41.386 [Service] 检测: com.kylin.read 广告角标 倒计时=21s 落地页词 继续观看提示 第N集
00:07:41.547 [Service] 上滑: pkg=com.kylin.read 原因=出现继续观看提示
```

**广告还剩 21 秒，但因为底部一直显示“上滑继续看短剧”，就直接上滑了。** 这行提示在广告播放期间
就一直挂在底部（是"这个广告位之后可以上滑继续"的常驻提示），并不是广告结束的标志。结果就是：
提前滑一次 → 广告照样播完 → 真正该滑的时候已经被冷却/次数限制挡住。

v2.1 的处理：

| 改动 | 说明 |
|---|---|
| "上滑继续看短剧"不再单独触发 | 只有**页面上没有正在走的倒计时**（倒计时消失或归零）时，才把它当成"广告结束卡片" |
| 新增“点击跳过广告” | 页面上有"跳过广告/关闭广告/跳过/关闭"按钮时，直接点掉（比滑一下更接近人工操作），并排除"跳过片头/片尾" |
| 上滑力度自动升级 | 三段不同起手区域，覆盖"广告按钮/WebView 吃手势"的情况 |
| 滑动区域裁剪 | 窗口 bounds 可能是 0,0~1280,**2800**，而屏幕只有 1280x**2659**（状态栏高度差），旧版会滑到屏幕外。现在取"窗口 ∩ 屏幕"，横屏、分屏、平板手机都适用 |
| 倒计时消失立刻重试 | 倒计时从"有"变"没有"=广告播完切结束卡片，之前白滑的次数清零，重新给 3 次机会 |
| 抓取节点延迟 5 秒 | 点按钮时前台是本应用，抓不到广告页；现在等 5 秒，够切回红果再抓 |
| 日志可滑动 / 全屏查看 | 日志区自带滚动（不再被外层 ScrollView 抢手势），点「全屏查看日志」可看完整内容并复制 |
| 打开日志存储位置 | 日志导出到 `Download/红果自动跳过/`，「打开日志存储位置」直接在文件管理器里打开该目录（失败则打开文件/复制路径） |
| 关键词说明 | 自定义关键词下方写明生效规则、写法建议、会误伤的词，并列出内置覆盖的词 |
| 横竖屏与尺寸适配 | 抓取/滑动全部按当前窗口与屏幕换算；界面加 `configChanges`，横竖屏切换不重建、参数不丢 |
| 修复“已安装 ✗” | Android 11+ 包可见性，manifest 增加 `<queries>`，现在能正确识别红果是否已安装 |

## 一、旧版为什么"平板能用、手机不行"，以及"漫剧能用、短剧不行"

旧版（v1.0）反编译后可以看到 3 个类：`MainActivity`、`HongguoAccessibilityService`、`AppLog`。问题都集中在检测链路：

| # | 旧版写法 | 后果 |
|---|---|---|
| 1 | 只在 `onAccessibilityEvent()` 回调里检测 | 手机 ROM（MagicOS / 鸿蒙）会合并、丢弃 `TYPE_WINDOW_CONTENT_CHANGED` 事件，一旦事件不来就**永远不检测**；平板系统事件派发更"宽"，所以能跑 |
| 2 | 在无障碍回调（主线程）里递归遍历整棵树，根节点为空时还 `Thread.sleep(200)` | 阻塞主线程：掉事件、手势派发失败、重则 ANR。手机刷新率和事件量都比平板大，症状被放大 |
| 3 | 只读 `getRootInActiveWindow()` 一个窗口 | 广告以独立窗口 / 悬浮窗 / 广告 SDK 窗口展示时，根节点不是红果的树 → 什么都看不到 |
| 4 | 检测规则只有两条：①文本"第N集" ②控件 `id=jer` 且文本为空 | `id=jer` 是**漫剧**的集数控件，**短剧**的广告页（广告角标 + 倒计时 + 跳过按钮）完全匹配不到，所以短剧永远不上滑 |
| 5 | `AD_KEYWORDS` 全是"立即下载/去游戏"这类落地页按钮 | 广告**播放中**的界面通常没有这些词，检测不到 |
| 6 | 清单里 `<service android:exported="false">` | 无障碍服务由 system_server 绑定，非本进程。新系统/部分 ROM 上会更严格地拒绝绑定 → 服务看起来"已授权"却连不上 |
| 7 | 参数默认值前后不一致：`check_interval` 默认取 `DEFAULT_COOLDOWN`；服务端 `confirm` 默认 2、界面默认 1；`debug_mode` 服务端 false、界面 true | 界面显示和实际行为不一致，用户以为按 1 次确认就滑，其实要 2 次 |
| 8 | 调试模式每收到一个事件就 dump 整棵节点树 | 手机上等于把主线程打死 |
| 9 | 声明了 `POST_NOTIFICATIONS` 但从不申请 | Android 13+ 通知静默丢弃，"已自动跳过广告"提示看不到 |

另外：旧版滑动坐标用的是**整屏** `heightPixels`（含状态栏/手势区），且判定逻辑是"看到广告特征就上滑"，
既没实现"检测广告播放完毕"，也容易在广告还在播时误触。

## 二、v2.0 的修复

1. **轮询为主、事件为辅**：检测跑在独立 `HandlerThread` 上，约 400ms 轮询一次；无障碍事件只用于"尽快再扫一次"，不再决定节奏。ROM 丢事件也不影响功能。
2. **多窗口扫描**：`getWindows()` 收集所有窗口（活动窗口 + 悬浮窗 + 广告 SDK 窗口），合并成一次检测；广告在独立窗口里也能识别。
3. **主线程零负担**：节点遍历全部在工作线程；删掉 `Thread.sleep`；日志只记录状态变化。
4. **两个 App 都支持**：
   - 通用规则：广告角标（"广告"/"AD"）、跳过按钮、倒计时（`5s`/`5秒`/`剩余3s`）、落地页词、`id` 里含 `ad/countdown/skip`；
   - "上滑继续观看"这类提示 = 广告已播完；
   - 漫剧额外保留旧版验证过的 `id=jer` 空文本特征（不破坏平板上的既有行为）；
   - 可在界面分别开关两个 App。
5. **真正的"广告播完"判定**（状态机 `AdStateMachine`）：
   - 倒计时还在走 → 不动；
   - 倒计时停住 / 广告角标持续 N 毫秒不变 → 认为播完，上滑；
   - 广告特征整体消失 → 上滑；
   - 出现"上滑继续观看" → 立刻上滑；
   - 冷却 2.5s、单段广告最多 3 次、上滑后 4s 静默，避免连环误滑。
6. **滑动坐标更稳**：优先用目标窗口的 bounds，退回整屏；起点/终点按百分比，避开状态栏。
7. **清单修正**：无障碍服务 `android:exported="true"`，运行时再刷一遍 `serviceInfo`（视图 id、交互窗口、事件类型），并加了 `settingsActivity`。
8. **Android 13+ 通知权限**运行时申请；通知渠道降为 LOW，不再打扰。
9. **参数体系统一**：所有默认可视化、可调，`Prefs` 里集中管理并做范围钳制；旧的 prefs 键名保留，升级不丢设置。
10. **诊断能力**：界面上「抓取当前页面节点」会把当前所有窗口的控件树（包名 / id / text / desc / bounds）写进日志并落盘；「导出」生成 txt。手机出问题可直接抓一份发出来，不必再猜。

## 五、手机上看不到效果时这样排查

1. 确认「设置 → 无障碍 → 红果广告自动跳过服务」已开启，且应用界面顶部显示「无障碍已连接 ✓」。
   荣耀/OPPO 等系统上，侧载应用的无障碍开关可能是灰的：点应用里「打开本应用设置」，右上角 ⋮ → **允许受限设置**，再回去开。
2. 荣耀 MagicOS / 华为鸿蒙额外要做：
   - 应用里点「电池优化设为不限制」，或手动：电池 → 应用耗电管理 → 不限制 / 允许后台活动；
   - 应用管理 → 红果自动跳过 → 允许「自启动」「关联启动」；
   - 最近任务里给本应用加锁。
   否则系统会在锁屏/后台一段时间后把无障碍服务清掉（这也是"平板正常、手机不行"的常见原因之一）。
3. 打开红果，等广告出现时点应用里的「抓取当前页面节点」，再点「导出」，把 txt 发出来。
   有了真实节点树就能精确加规则（比如短剧的广告倒计时控件 id）。

## 七、已知限制

- 只在电脑侧做了规则级单元测试和构建验证，**没有在荣耀 MagicOS 真机上跑过**（当前环境没有连接设备）。
- 如果某个版本的广告页完全没有任何可读节点（纯画面视频 + 图片角标），无障碍层面无法识别，需要用「抓取当前页面节点」拿到实际控件再加规则。
- 广告跳转到外部 App（电商/游戏）时，前台包名不再是红果，本应用不会跟随跳转操作；等回到红果后继续检测。
